## 1. 로그인 유지가 "로그아웃 전까지" 가 아니라 발급 후 30일이다

- **문서**: `docs/03-requirements.md:37` R24 — "로그아웃하기 전까지는 앱을 다시 열어도 로그인 상태가 유지되어야" 한다.
  `docs/04-features.md:23` F8 결과도 "로그인한 뒤에는 로그아웃(F12)하기 전까지 앱을 다시 열어도 로그인 상태가 유지된다" 로 같다. 둘 다 만료를 말하지 않는다.
- **결정 · 구현**: 세션 TTL 은 **발급 후 고정 30일**이다(#78 D2). 쓰더라도 연장하지 않는다(rolling · sliding 없음).
  `auth_sessions.expires_at = created_at + 30일` 이고 쿠키 `Max-Age` 도 30일이다. 서버가 `expires_at` 을 강제하므로
  30일이 지나면 로그아웃하지 않았어도 재로그인해야 한다.
  근거: 무기한 세션은 기기를 잃었을 때 회수할 방법이 없다. rolling 을 쓰면 만료가 사실상 사라진다.
- **고쳐야 할 곳**:
  - `docs/03-requirements.md:37` — R24 에 "30일 이내" 조건을 넣는다.
  - `docs/04-features.md:23` — F8 결과의 "로그아웃 전까지" 문장에 같은 조건을 넣는다.
  - `docs/07-screens.md` 첫 화면 분기 — 만료된 세션이 로그인 화면으로 가는 경로가 분기 설명에 없다.

## 2. 로그인 세션을 서버에 저장한다

- **문서**: `docs/06-data.md:60` — "로그인 유지는 **기기 쪽에서 유지하는 상태**로 보고 이 표의 저장 항목에 넣지 않았다.
  05 상태값의 「로그인」 상태도 **서버에 남길 값이 아니다**."
- **결정 · 구현**: `auth_sessions` 테이블을 만들어 **서버에 기기별 세션 행을 저장한다**(#78 D2).
  쿠키에는 opaque 256-bit token 이 들어가고 DB 에는 그 SHA-256 hex 만 둔다.
  이래야 로그아웃이 "그 기기의 세션만 즉시 무효" 로 동작하고(다른 기기는 유지), 만료를 서버가 강제할 수 있다.
  기기에만 두면 서버가 세션을 끊을 수단이 없다.
- **고쳐야 할 곳**:
  - `docs/06-data.md:60` — 이 문단을 지우고 「로그인 세션」 저장 그룹을 새로 넣는다(기기별 행 · token hash · 발급 시각 · 만료 시각 · 로그인 제공자).
  - `docs/05-policy.md` — 「로그인」 상태값이 서버 저장 값이 아니라던 서술을 함께 본다.

## 3. 사용자 UID 형식과 계정 연결 모델이 다르다

- **문서**: `docs/06-data.md:14` 는 UID 예시를 `u_7f3a91c2` 로 적는다. `:15` · `:16` 은 「소셜 로그인 제공자」와
  「소셜 계정 식별자」를 **사용자 항목 안의 값**으로 둔다. `:19` 는 계정 상태를 `가입 중` / `가입 완료` 로 쓴다.
- **결정 · 구현**: UID 는 `users.id uuid`(`gen_random_uuid()`)다. 제공자 · 소셜 계정 식별자는 사용자 컬럼이 아니라
  **별도 `oauth_accounts` 테이블**이고 PK 가 `(provider, provider_account_id)` 다 — 이 형태라야 같은 소셜 계정이
  두 UID 에 붙는 것을 DB 가 막는다(P11). 계정 상태 저장값은 `signing_up` / `active` 다(화면 표기는 문서대로 한글).
- **고쳐야 할 곳**:
  - `docs/06-data.md:14` — UID 예시를 uuid 로 바꾼다.
  - `docs/06-data.md:15-16` — 제공자 · 식별자를 별도 저장 그룹(소셜 계정 연결)으로 분리한다.
  - `docs/06-data.md:19` — 계정 상태의 저장값과 화면 표기를 구분해 적는다.

## 6. `src/server/db/schema.ts` 만 `import "server-only"` 가 없다

- **계약**: #79 「소유 파일」 — "server action 파일(`"use server"`)을 제외한 모듈은 `import "server-only"` 로 시작한다."
- **구현**: `schema.ts` 한 파일만 빼고 전부 붙였다. `drizzle.config.ts` 가 이 파일을 가리키는데 `drizzle-kit` 은
  Next 밖에서 도는 CLI 라 Next 내부 alias 인 `server-only` 를 해석하지 못한다
  (`npm run db:generate` 가 `Cannot find module 'server-only'` 로 죽는다).
  #79 가 `server-only` 를 dependency 로 추가하는 것을 금지하므로 package 를 넣지 않고 이 파일에서만 뺐다.
  이 파일은 테이블 메타데이터뿐이고 secret · 접속 · 쿼리가 없다. 실제로 DB 에 닿는 `client.ts` 가 `server-only` 를
  들고 있어서 클라이언트 컴포넌트가 DB 로 가려 하면 여전히 빌드가 깨진다.
- **고쳐야 할 곳**: 문서가 아니라 **#79 계약 문구**다. 담당자 확인이 필요하다 — 「`src/server/**` 전부」에서
  「drizzle-kit 이 직접 읽는 schema 파일 제외」로 예외를 명시할지 정한다.

## 7. `npm run dev` 포트가 3001 이면 로그인이 실패한다

  터미널에 주소를 찍는다" 로, 3001 이어도 괜찮다고 읽힌다.
