## 1. 네 상태 → 이 화면의 도메인 상태

- **문서**: `docs/07-screens.md:14` — 「모든 화면은 **불러오는 중 · 빈 상태 · 오류 · 정상** 네 상태를
  구분해 보여 주고, 오류일 때는 사용자가 할 수 있는 다음 행동(다시 시도 등)이 보인다.」
- **디자인 · 구현**: 이 화면에는 **실패할 요청이 없다.** 서버도 API 도 없고 실제 GPS 측정은 제외
  범위라, 요청 기반 loading · error 를 만들면 전부 가짜가 된다. 대신 이슈가 정한 도메인 상태
  네 가지(정상·구역 내 / 정상·구역 밖 / GPS 약함 / 시작 직후)를 구분했다. 가짜 Promise 나 query
  error 를 넣지 않았다.
- **근거**: 이슈 #40 「상태 정의」 · 결정 이력(2026-09-14) 「이 화면에서는 위 상태 정의가 generic
  4상태 문구보다 우선한다」 · `docs/SCREEN_ASSIGNMENTS.md:109` 공통 완료 조건.
- **고쳐야 할 곳**: `docs/07-screens.md:14` — 「네 상태」를 모든 화면에 일괄 적용하는 문장을,

## 4. 확대 · 축소 버튼의 터치 영역은 48×41 이다 (48×48 이 아니다)

- **문서**: `docs/07-screens.md:15` — 「누를 수 있는 영역은 최소 48×48dp」.
- **디자인 · 구현**: 디자인 L231-234 의 확대 · 축소는 **34×34 버튼 두 개가 맞붙은 스택**이다(총
  69px). 시각 크기를 유지하면서 둘 다 세로 48px 을 가지려면 96px 이 필요해 서로 겹친다 — 겹치면
  아래 버튼의 터치 영역이 위 버튼을 먹는다. 그래서 `::after` 를 **바깥쪽으로만** 늘렸다:
  가로는 48px 을 채우고(34+7+7), 세로는 맞붙은 변을 침범하지 않아 41px(34+7)이다.
  재중심 버튼(46×46)은 독립이라 48×48 을 채웠다. 기법은 `BackButton.tsx:26` 과 같다.
- **근거**: 이슈 #40 결정 이력 — 「디자인의 34×34 와 48×48 규칙이 충돌해, 시각 크기는 디자인대로
  두고 터치 영역만 넓힌다」.
- **고쳐야 할 곳**: `docs/07-screens.md:15` — 「최소 48×48」에 맞붙은 컨트롤 스택의 예외를 적거나,
