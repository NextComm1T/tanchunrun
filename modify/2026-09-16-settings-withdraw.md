## 1. 「개인 최고 기록 · 랭킹 집계 행 전부 삭제」 — 지울 행이 없다

- **문서**: `docs/05-policy.md:26` P13 · `docs/06-data.md:58` 「회원 탈퇴(F13) 시 삭제 범위」 —
  UID 를 가리키는 「러닝 세션」 · 「GPS 측정 지점」 · **「개인 최고 기록」 · 「랭킹 집계」 행 전부**
  를 삭제한다.
- **디자인 · 구현**: D6 이 **B(파생)** 로 확정돼(#78 ledger · 2026-09-16) `personal_bests` ·
  `ranking_aggregates` **물리 테이블이 없다.** 공개 canonical source 는
  `run_sessions WHERE save_state = 'saved'` 하나이고, 개인 최고 기록 · 랭킹은 그때그때 계산한다.
  그래서 `withdraw()` 는 `users` 한 행만 지우고 나머지는 `ON DELETE CASCADE` 가 가져간다 —
  `run_sessions` 가 사라지는 순간 파생값도 함께 사라지므로 **결과는 문서가 요구한 것과 같다.**
  화면의 삭제 안내 목록(디자인 L580)에 「랭킹 반영 데이터」가 남아 있는 것도 그래서 옳다.
- **고쳐야 할 곳**: `docs/06-data.md:58` 의 삭제 범위 문장. 「행 전부」가 아니라 「그 UID 의 러닝
  세션이 사라지면 개인 최고 기록 · 랭킹 집계도 함께 사라진다(파생 · D6 = B)」로 바꾼다.
  `docs/05-policy.md:26` P13 도 같은 표현을 쓴다.

## 2. 서버가 그리는 화면에는 「불러오는 중」이 없다

- **문서**: `docs/07-screens.md:12` 공통 인수 조건 ① — 모든 화면이 **불러오는 중 · 빈 상태 ·
  오류 · 정상** 네 상태를 구분한다.
- **디자인 · 구현**: 설정 · 동의 · 탈퇴 세 화면의 값은 server component 가 **기다렸다가** 그린다.
  화면이 뜬 시점에는 값이 이미 있어서 로딩 자리가 생기지 않는다. 억지로 만들려면 가짜
  Promise 를 넣어야 하는데 그건 `ARCHITECTURE.md` 가 금지한 가짜 상태다.
  - 「불러오는 중」이 **실제로 성립하는 곳은 위치 권한 하나뿐**이다. 브라우저에 물어야 알 수 있어
    client 에서 조회하고, 그동안 설정 목록의 「위치정보」 줄과 위치정보 화면의 상태 카드가
    스켈레톤을 보인다.
  - 이 Issue 에서 `?state=` · `?location=` · `?permission=` · `?session=` 쿼리 계약을 **전부 없앴다.**
    상태를 URL 로 고르던 방식이 사라졌으므로 오류의 「다시 시도」도 링크가 아니라
    `router.refresh()`(서버 조회) · 재조회(권한)를 실제로 부르는 버튼이 됐다.
- **고쳐야 할 곳**: `docs/07-screens.md:12`. 「서버가 렌더 전에 값을 확보하는 화면은 불러오는 중을
  만들지 않는다」는 단서를 단다. [20260914-settings-withdraw.md](20260914-settings-withdraw.md)
  4번이 같은 제안을 이미 했고, 이번엔 서버가 실제로 붙은 뒤에도 같은 결론이 나왔다.

## 3. 위치 권한 상태가 2종에서 4종이 됐다

- **문서 · 디자인**: 디자인은 `s.gpsReady` 하나로 갈라 **「사용 중」 / 「권한 필요」 둘뿐**이다
  (L1317-1318).
- **디자인 · 구현**: 실제 Permissions API 를 물으면 `granted` · `denied` · **`prompt`**(아직 묻지
  않음) 셋이 오고, API 자체가 없는 브라우저(Safari 계열)가 넷째다.
  - 화면 문구는 **디자인 2종을 유지한다** — `prompt` 는 「권한 필요」로 묶었다. 앱이 위치를 쓸 수
    없다는 결과와 사용자가 할 일(허용하기)이 거부와 같기 때문이다.
  - 조회 수단이 없는 경우만 「확인 불가」(muted)로 따로 뒀다. **조회에 실패한 것과는 다르다** —
    그건 오류 카드 + 다시 시도다. 지원하지 않는 브라우저에 「다시 시도」를 보이면 고칠 수 없는
    것을 고치라고 하는 셈이다.
- **고쳐야 할 곳**: `docs/07-screens.md:29` 설정 화면의 「보이는 것」과 위치정보 화면 상태 목록.
  권한 값이 2종이 아니라는 것과, 「확인 불가」가 빈 상태라는 것을 적는다.

## 4. 「위치 권한 허용하기」 버튼이 실제로 브라우저에 묻는다 + 거부 안내를 더했다

- **문서 · 디자인**: 디자인 L470 은 미허용일 때 버튼만 그리고 눌렀을 때의 동작을 정하지 않는다.
  #47 은 실제 권한 요청을 제외 범위로 뒀고, 그때까지 버튼은 **아무 일도 하지 않았다.**
- **디자인 · 구현**: 권한 상태를 실제로 보여 주게 된 이상 그 옆의 버튼이 거짓말을 하면 안 되므로
  연결했다. Permissions API 에는 요청하는 수단이 없어서 `getCurrentPosition()` 으로 프롬프트를
  띄우고, **받은 좌표는 쓰지도 저장하지도 않고 버린다**(묻는 것이 목적이다).
  - 한 번 거부한 상태에서는 브라우저가 다시 묻지 않는다. 눌러도 아무 일이 없는 것처럼 보이므로
    **디자인에 없는 안내 한 줄**(「브라우저 설정의 사이트 권한에서 위치를 허용해 주세요」)을
    버튼 아래에 더했다. 토큰은 `text-note` · `text-muted` 로 기존 캡션과 같다.
- **고쳐야 할 곳**: 디자인 원본(`탄천런.dc.html` L470 부근)에 거부 상태의 안내가 없다 — 문서가
  아니라 디자인에 추가할지 팀 판단이 필요하다.

## 5. 동의 「확인 불가」의 뜻이 바뀌었다

- **문서**: `docs/04-features.md:23` F8 흐름 — 가입 단계에서 필수 동의를 받아야 서비스에 들어온다.
  그래서 정상 상태는 「동의 완료」 하나다.
- **디자인 · 구현**: `hasCurrentConsent()`(#80 · D5)는 **현재 버전**까지 같은 행이 있을 때만 참이다.
  고지 문구가 바뀌어 버전이 오르면 옛 버전에만 동의한 계정은 「확인 불가」가 된다 — 지금 화면에
  보이는 문구에 대한 동의 기록이 실제로 없기 때문이고, 「동의 완료」로 적으면 읽지 않은 문구를
  확인해 준 셈이 된다. MVP 는 버전이 하나라 실제로는 나오지 않는다.
- **고쳐야 할 곳**: `docs/05-policy.md` 의 동의 관련 줄. 동의가 **버전 단위**라는 것과, 버전이
  오르면 재동의가 필요하다는 것을 적는다(지금 문서에는 버전 개념이 없다).
