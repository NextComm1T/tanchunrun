## 1. 닉네임 중복을 입력 중에 판정하지 않는다

- **문서 · 기존 구현**: `docs/05-policy.md:23` P10 은 중복을 재입력 사유로 열거하고, 디자인
  L1200 도 입력 중 안내 문구로 「이미 사용 중인 닉네임입니다.」를 보여 준다. 기존 화면은
  사용 중인 닉네임 13개를 화면 안에 상수로 박아 두고 타이핑 중에 판정했다.
- **디자인 · 구현**: 목록 상수를 지우고 **제출 후 서버 응답으로만** 중복을 안내한다. 문구는
  그대로 「이미 사용 중인 닉네임입니다.」이고 나타나는 **시점만** 달라졌다.
  판정 근거는 `users` 의 `lower(nickname)` unique index 다.
  - 이유는 정확성이다. 화면이 미리 판정하려면 목록을 받아 와야 하는데, 받아 온 순간부터
    제출까지 사이에 다른 사람이 같은 닉네임을 가져갈 수 있다. 두 브라우저가 동시에 같은
    닉네임을 제출하면 둘 다 "사용 가능" 을 보고 둘 다 통과한다. DB 제약에 맡기면 반드시
    한쪽만 성공한다(#80 AC 2번).
- **고쳐야 할 곳**: `docs/05-policy.md:23` P10 의 실패 사유 목록에 「중복은 저장 시점에
  판정된다」를 덧붙인다. `docs/07-screens.md:46` 의 입력 중 안내 열거도 같이 본다.

## 2. 저장 실패 상태가 새로 생겼다

- **문서**: 디자인 L1197 에 「저장에 실패했습니다. 다시 시도해주세요.」 문구가 있지만,
  저장할 곳이 없던 시점의 구현은 이 상태를 만들지 않았다
  (`modify/2026-09-14-signup-nickname.md` · `modify/2026-09-14-settings-nickname.md`).
- **디자인 · 구현**: 동의 · 최초 닉네임 · 닉네임 수정 세 곳 모두 실제 실패 경로가 생겨서
  문구를 붙였다. **성공했을 때만 화면을 옮긴다** — 실패하면 그 자리에 머무르며 오류를 보인다.
  동의 화면은 디자인에 없는 오류 블록이라 로그인 · 로그아웃 실패 안내와 같은 토큰
  (`border-error-border bg-error-soft text-error` · `role="alert"`)을 썼다.
- **고쳐야 할 곳**: `docs/07-screens.md:12` 의 화면 상태 4종에 가입 화면의 오류 상태를 반영한다.

## 3. 동의 버전이 코드 상수다

- **문서**: `docs/06-data.md` 에 동의 저장 칸이 없다.
- **디자인 · 구현**: D5 확정값대로 `consents(user_id, consent_type, version, agreed_at)` 을
  저장하고, `version` 은 고지 문구 상수 옆의 `PRIVACY_CONSENT_VERSION`
  (`src/app/signup/consent/consentSections.ts`)이다. **문구를 바꿀 때 사람이 값을 올린다.**
  같은 사용자가 같은 버전으로 다시 눌러도 기존 행과 `agreed_at` 을 갱신하지 않는다
  (최초 동의 시각 유지). IP · User-Agent · 기기 식별자 · 철회 이력은 저장하지 않는다.
- **고쳐야 할 곳**: `docs/06-data.md` 에 동의 저장 항목을 추가한다.

## 4. 가입 중 가드를 `src/proxy.ts` 에 뒀다 — 「루트」가 아니다

- **문서 · 이슈**: #80 본문은 「루트 `proxy.ts`(신규)」라고 적었다.
- **디자인 · 구현**: 이 저장소는 `src/app` 구조라서 Next 16 이 proxy 를 `src/proxy.ts` 에서
  찾는다. 저장소 루트에 두면 **빌드가 조용히 무시한다**(`middleware-manifest` 가 비고
  빌드 출력에 `Proxy` 줄이 나오지 않는다). 그래서 `src/proxy.ts` 다.
- **고쳐야 할 곳**: 없음. #80 본문의 표현만 실제 경로와 다르다.

## 5. 가드 범위는 「가입 중」뿐이다

- **문서 · 이슈**: #80 AC 8번 — 「가입 중 사용자가 `/home` · `/records` 를 직접 입력해도
  가입 흐름으로 돌아간다」.
- **디자인 · 구현**: 그대로 구현했고 **로그아웃 사용자는 막지 않는다.** #80 계약이 가입 중만
  요구하고, 로그인 없이 볼 수 있는 화면들은 아직 전부 mock 이라 새는 데이터가 없다.
  실데이터가 붙는 #81 이후 각 화면이 자기 데이터를 막는다.
- **고쳐야 할 곳**: 없음(후속 Issue 범위).
