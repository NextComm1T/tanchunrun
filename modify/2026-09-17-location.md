# 2026-09-17 — 위치정보 화면(`/settings/location`) · denied 상태의 CTA 제거 (#124)

> 이 파일은 기록일 뿐, 문서를 고치지 않았다. 폴더 규칙은 `modify/2026-09-14.md` 머리말을 따른다.
> `modify/2026-09-14-location.md` 가 이 화면의 이전 차이를 기록해 뒀다 — 이 파일은 #124 가
> 새로 더한 것만 적는다.

## 1. denied 상태에서 「위치 권한 허용하기」 버튼을 뺐다 — 정본은 항상 버튼을 그린다

- **문서 · 이슈**: `docs/05-policy.md` P1 · `docs/07-screens.md:23`은 "권한 설정으로 가는 길"만
  요구하고, 그 화면의 CTA가 상태별로 어떻게 달라야 하는지는 규정하지 않는다.
- **디자인**: 정본 `탄천런.dc.html` L470은 `locationDenied` 하나로만 버튼을 켜고 끈다 —
  `prompt`(아직 묻지 않음)와 `denied`(이미 거부함)를 구분하지 않고 늘 같은 활성 버튼을 그린다.
  `modify/2026-09-14-location.md` 5번이 이미 "디자인은 권한과 GPS 확보를 한 값으로 뭉뚱그린다"고
  기록했는데, 이번엔 `denied`/`prompt` 구분도 정본에 없다는 같은 종류의 빈틈이다.
- **구현**: `denied`에서 버튼을 누르면 브라우저가 다시 프롬프트를 띄우지 않아(권한 API 특성상
  당연한 동작) 고장 난 버튼처럼 보이는 문제(#124 목적)가 있었다. 버튼 대신 이미 있던 안내
  문구("이미 거부한 상태라 브라우저가 다시 묻지 않습니다…")를 그 자리의 주 콘텐츠로 올렸다 —
  새 문구를 만들지 않았다. `prompt` · `unknown`은 정본대로 버튼을 그대로 유지한다
  (`src/app/settings/location/LocationPermissionPanel.tsx`).
- **고쳐야 할 곳**: 정본을 다시 캡처할 때 디자인 담당이 `denied` 전용 상태를 추가할지 판단한다.
  문서 쪽 변경은 불필요 — 문서는 애초에 이 수준의 세부를 규정하지 않는다.

## 2. 브라우저 설정에서 돌아왔을 때 권한 상태를 조용히 다시 읽는다

- **문서**: `docs/07-screens.md:23` · `docs/05-policy.md` P1 은 「권한 설정으로 가는 길」까지만
  정하고, **거기서 권한을 바꾸고 돌아온 뒤**의 화면 갱신은 규정하지 않는다. 정본 디자인에도
  해당 동작이 없다.
- **디자인 · 구현**: 1번이 버튼을 없애면서 이 화면의 유일한 복구 경로가 「브라우저 설정에서
  고치고 돌아오기」가 됐다. 그런데 돌아와도 화면이 그대로 `denied` 면 고친 것이 반영되지
  않은 것처럼 보인다. `status.onchange` 구독이 걸리지 않는 경우(탭이 오래 백그라운드에
  있었거나 OS 수준 설정을 거친 경우)를 대비해 `visibilitychange` · `focus` 에서 권한을 한 번
  더 조회한다(`src/app/settings/useLocationPermission.ts`). `state` 는 건드리지 않아 로딩
  스켈레톤이 다시 뜨지 않고, Permissions API 가 없는 브라우저는 그대로 넘어간다.
- **고쳐야 할 곳**: `docs/07-screens.md:23` 위치정보 화면의 상태 목록에 「브라우저 설정에서
  돌아오면 권한 상태를 다시 읽는다」를 덧붙인다.

## 3. denied 안내를 오류 색이 아니라 경고 색으로 둔다

- **문서**: `docs/ARCHITECTURE.md` 「디자인 토큰 · 색」은 `error` 계열을 「오류」에,
  `warning` 계열을 「GPS 약함 · 경고」에 배정한다. 어느 쪽인지는 규정하지 않는다.
- **디자인 · 구현**: 권한 거부는 앱이 실패한 것이 아니라 **사용자가 고른 상태**다. 1번이
  이 문구를 그 자리의 주 콘텐츠로 올리면서 error 계열(빨강)을 썼다가 warning 계열로 바꿨고,
  렌더와 함께 나타나는 안내라 `role="alert"` 가 아니라 `role="status"` 로 둔다.
- **고쳐야 할 곳**: 없다. 토큰 표의 기존 배정을 그대로 따른 것이다.
