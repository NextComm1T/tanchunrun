## 브라우저 설정에서 권한을 바꾸고 돌아오면 GPS 판정을 다시 한다

- **문서**: `docs/05-policy.md` P1 과 `docs/07-screens.md:47` 은 「GPS 확인 완료 = ① 권한 허용
  ② 현재 위치 1회 이상 확보」와 비준비 상태의 안내까지만 정하고, **그 확인을 언제 다시 하는지**는
  규정하지 않는다. 정본 디자인 `탄천런.dc.html` 에도 해당 동작이 없다(L724-730 은 안내 카드의
  모양만 그린다).
- **디자인 · 구현**: `useGeolocationReady`(`src/app/home/useGeolocationReady.ts`)가 마운트와
  「다시 확인」(#119) 때만 판정하던 것을, `permissions` 의 `status.onchange` · `visibilitychange` ·
  `focus` 에서도 권한을 다시 읽도록 했다. `denied` 로 바뀌면 `firstFix` 를 버리고 시작을 막고,
  `granted` · `prompt` 로 풀렸을 때는 **`denied` 로 막혀 있던 경우에만** 첫 측위를 다시 시작한다.
  - 이유: `denied` 안내의 유일한 복구 경로가 「위치정보 설정 보기 → 브라우저 설정에서 허용 →
    돌아오기」인데, 돌아와도 새로고침 전까지 「위치 권한 필요」에 머물렀다. 반대로 `ready` 뒤에
    권한을 끄면 홈은 계속 시작 가능으로 보였다.
  - `unavailable`(권한은 있는데 좌표를 못 받음)은 권한 문제가 아니라서 재측위를 걸지 않는다 —
    그 자리는 #119 의 「다시 확인」 몫이다.
  - 설정 > 위치정보 화면이 #124 에서 이미 같은 방식을 쓴다(`modify/2026-09-17-location.md` 2번).
    같은 앱 안에서 두 화면의 동작이 달랐던 것을 맞춘 것이다.
  - Permissions API 가 없는 브라우저(Safari 일부)는 `status` 가 없어 그대로 넘어간다.
- **고쳐야 할 곳**: `docs/07-screens.md:47` 러닝 시작 화면의 상태 목록과 `docs/05-policy.md` P1 에
  「권한이 바뀌면 GPS 확인 완료 판정을 다시 한다」를 덧붙인다. `docs/07-screens.md:23` 위치정보
  화면에 같은 줄을 더할 때(`modify/2026-09-17-location.md` 2번) 함께 본다.
