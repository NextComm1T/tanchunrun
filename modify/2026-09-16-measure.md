## 2. P5 「양 끝이 모두 Zone 안인 조각」은 중점 판정으로 구현했다

- **문서**: `docs/05-policy.md:18` P5 — 「경계에 경계점을 넣어 쪼갠 뒤 **양 끝이 모두 Zone 안인
  구간만** 인정 거리에 더한다」
- **구현**: 조각의 **중점**으로 판정한다(`measure.ts` `measureLeg`). D9 에서 경계 위 점을 Zone
  안으로 정했으므로 경계점은 정의상 늘 「Zone 안」이 되고, 그러면 모든 조각이 「양 끝이 Zone 안」이
  되어 조건이 아무것도 걸러내지 못한다. 중점 판정은 P5 가 뒤집은 규칙(한쪽만 안 · 둘 다 밖인데
  가로지름)을 그대로 만족하고, 경계가 오목해 한 구간이 Zone 을 두 번 드나드는 경우까지 맞는다.
- **고쳐야 할 곳**: `docs/05-policy.md:18` P5 의 「양 끝이 모두 Zone 안인 구간만」을 「경계점으로
  쪼갠 뒤 Zone 안을 지나는 조각만」으로 다듬는다.

## 3. route point 의 `inZone` 은 점의 속성이지 조각의 속성이 아니다

- **문서**: `docs/ARCHITECTURE.md` `TancheonMap` — 「`inZone` 이 바뀌는 점은 앞뒤 선이 함께 가져서
  경계에서 색이 갈린다(R11)」
- **구현**: 측정 지점은 자기 좌표로 판정하고, 경계점은 D9 대로 `true` 다. 색을 「양 끝이 모두
  `inZone` 일 때만 인정색」으로 칠하면 **경계가 오목해 한 구간이 Zone 을 두 번 드나드는 자리**에서
  실제 인정 구간과 색이 어긋날 수 있다. 거리 계산은 중점 판정(2번)이라 영향이 없고, 색만 그렇다.
  점 하나에 boolean 하나로는 조각별 상태를 담을 수 없어서 필드를 늘리지 않고 남겨 둔다.
- **고쳐야 할 곳**: 표시 쪽(#84 · #86)에서 실제로 어긋나 보이면 그때 `route_points` 에 조각 단위
  필드를 더할지 정한다. 지금은 후보로만 둔다.

## 4. 평균 페이스의 「총 시간」 출처를 인자로 받는다

- **문서**: `docs/06-data.md` 「러닝 세션 · 평균 페이스」와 이슈 #82 는 「평균 페이스 = 총 시간 /
  총 거리」라고만 하고 **총 시간을 누가 주는지**는 정하지 않았다(D13 OPEN).
- **구현**: `measure(points, { elapsedMs })` 의 **선택 인자**다. 넘기지 않으면 첫 측정 지점과 마지막
  측정 지점의 시각 차를 쓴다. domain 입력에는 서버 `started_at` 이 없어서, 서버 시각 기준 duration 은
  #85 finalization 이 넣게 했다. 기존 계약을 깨지 않는 추가다.
- **고쳐야 할 곳**: D13(종료 시각 authoritative source)이 확정되면 `docs/06-data.md` 의 평균 페이스
  칸에 「총 시간 = 서버 `started_at` ~ 종료 시각」을 명시한다.

## 5. `recordedAt` 은 epoch ms 숫자다

- **문서**: `docs/06-data.md` 「GPS 측정 지점 · 기록 시각」은 시각 값이라고만 한다.
- **구현**: domain 은 `number`(epoch ms)로만 다룬다. `Date` · timezone 이 끼면 순수 계산이 실행 환경을
  타기 때문이다. DB `timestamptz` ↔ epoch ms 변환은 **#83 이 API · 저장 경계에서** 한다.
- **고쳐야 할 곳**: `docs/06-data.md` 「기록 시각」에 저장은 `timestamptz`, 계산은 epoch ms 라고 적는다.

## 6. GPS 끊김 판정과 저장 주기가 정해졌다 (D10)

- **문서**: `docs/06-data.md:34` 저장 주기가 `[?]` 였고, `docs/05-policy.md:15` P2 는 제외가
  「신호를 잃은 **즉시**」 적용된다고만 한다.
- **구현**(`src/domain/measure/fix.ts`): 저장 주기는 **accept 된 fix 마다**이고, accept 는
  `MIN_SAMPLE_INTERVAL_MS = 1000` · `MAX_ACCURACY_M = 30` 으로 정해진다.
  P2 의 「즉시」는 **두 가지로 나뉜다** — ① error · `PERMISSION_DENIED` · unusable fix 는 **관측
  즉시** gap pending 이고, ② callback 이 조용한 것만으로는 끊김이 아니라 다음 accept 에서
  `recordedAt` 차가 `GPS_GAP_MS = 5000` 을 넘을 때 **뒤늦게(post-hoc)** segment 를 끊는다.
  `GPS_WARNING_AFTER_MS = 2000` 은 화면 경고(P3) 기준일 뿐 제외 기준이 아니다.
- **근거**: [decision] D10 · #78 ledger
  (https://github.com/NextComm1T/tanchunrun/issues/78#issuecomment-5684103710)
- **고쳐야 할 곳**: `docs/06-data.md:34` 의 `[?]` 를 지우고, `docs/05-policy.md:15` P2 에 위 ①②
  구분을 적는다.
