## 1. 결과 화면에서 뒤로 가기의 목적지를 보장하지 않는다

- **문서**: `docs/07-screens.md:59` — "결과 화면 | 다음 러닝을 하러 러닝 시작 화면으로 돌아간다 · 휴대폰
  뒤로 가기를 눌러도 같다 | 러닝 시작 화면 | P7". 뒤로 가기를 누르면 러닝 시작 화면으로 간다고 정의한다.
- **디자인 · 구현**: 정본(`탄천런.dc.html` L298-374)의 결과 화면에는 back UI 가 없다. 구현도 `Header`
  없이 `AppShell` 만 쓰고, 브라우저/기기의 뒤로 가기를 가로채지 않는다(이슈 #41 결정 이력 2026-09-14).
  정상 흐름(러닝 진행 → 종료 → 결과)에서는 러닝 진행 화면(#40)이 `router.replace` 계열로 이동해 히스토리에
  남지 않으므로, 뒤로 가기는 그 이전 화면(보통 홈 달리기 탭)으로 간다 — 문서가 말하는 "러닝 시작 화면"과
  결과적으로 비슷할 수 있지만 보장된 동작은 아니다. `/result/[sessionId]` 로 직접 들어온 경우(mock 확인
  포함)의 뒤로 가기 목적지는 브라우저 기본 동작에 맡기며 이 화면이 관여하지 않는다.
- **고쳐야 할 곳**: `docs/07-screens.md:59` — 뒤로 가기 목적지를 "보장" 이 아니라 "정상 흐름에서 대체로
  그렇게 되는 부수 효과"로 다시 적어야 한다.

## 2. 이동 버튼을 `<button onClick>` 이 아니라 링크로 구현

- **문서 · 디자인**: `탄천런.dc.html` L367·L369 는 `<button onClick="{{ onViewRanking }}">` ·
  `<button onClick="{{ onViewRecords }}">` 다.
- **구현**: `next/link` 의 `<Link href="/ranking">` · `<Link href="/records">`. 디자인 원본의 `onClick`
  은 단일 HTML 안에서 도는 데모 상태머신용이고, 실제 앱에서는 route 이동이라 링크가 맞다
  (`modify/2026-09-15-bottomnav.md` 2번과 같은 종류의 차이). 시각 결과는 동일하다.
- **고쳐야 할 곳**: 없음. 구현 수단 차이일 뿐 화면 사양이 달라지지 않는다.
