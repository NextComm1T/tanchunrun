# 2026-09-17 — 러닝 진행 화면(`/running`) · read-only 기기의 「여기서 종료」 (#116)

> 이 파일은 기록일 뿐, 문서를 고치지 않았다. 폴더 규칙은 `modify/2026-09-14.md` 머리말을 따른다.
> read-only 오버레이 자체는 `modify/2026-09-16-run-session.md` 4번이 기록했다 — 이 파일은 #116 이 더한 것만 적는다.

## 1. 러닝 진행 화면에서 나가는 길이 「러닝 종료 버튼」 말고 하나 더 생겼다

- **문서**: `docs/07-screens.md:53-56` 은 러닝 진행 화면에서 결과 화면으로 가는 전이를 전부 「러닝 종료 버튼
  클릭」으로 적고, `:56` 은 「이 화면에서 나가는 이동은 러닝 종료 버튼(04 F2 → F9)뿐이다」라고 못박는다.
  `:36` · `:41` 은 다른 기기에서 다시 열거나 로그인하면 「러닝 진행 화면(이어서 측정)」으로 간다고만 적는다.
- **디자인 · 구현**: #78 D14 가 read-only 기기의 액션을 「이 기기에서 이어서 측정」·「여기서 종료」 **두 개**로
  정했다. 정본 디자인(`탄천런.dc.html`)에는 read-only 상태 자체가 없다. `src/app/running/TrackerGate.tsx` 의
  read-only 오버레이에 **「여기서 종료」** 를 더했다.
  - 누르면 바로 끝내지 않고 **확인 단계**를 한 번 거친다 — 러닝이 끝나는 동작이고 되돌릴 수 없다.
    확인 문구에 **다른 기기가 아직 보내지 못한 기록이 저장되지 않을 수 있다**는 것을 적는다(D14).
  - 확인하면 인수(generation +1)한 뒤 **점 0개(`lastRawSeq = 0`)로 종료 의사**를 남기고 결과 화면으로 간다.
    결과 화면이 기존 결과 복구(#85)로 종료를 마친다 — 거리 · 페이스 · 랭킹은 **모든 generation 의 서버 저장
    점**으로 계산되고, 이 기기에서 새로 측정한 점은 없다.
  - 설계 근거와 다른 안(별도 서버 경로)과의 비교는 #116 코멘트에 있다.
- **고쳐야 할 곳**: `docs/07-screens.md:53-56` 근처에 「러닝 진행 화면(다른 기기에서 진행 중 · read-only) —
  「여기서 종료」 확인 → 결과 화면」 전이를 덧붙이고, `:56` 의 「나가는 이동은 러닝 종료 버튼뿐」을 고친다.
  `:36` · `:41` 에는 다른 기기에서 열면 **read-only 로 보이고 두 액션 중 하나를 고른다**는 것을 적는다.

## 2. 종료를 누른 뒤 탭이 죽었다가 다시 열면 결과 화면으로 간다

- **문서**: `docs/05-policy.md` P14 와 `docs/07-screens.md:55` 는 종료 처리 실패를 결과 화면의 오류 · 「다시
  시도」로 보낸다. **종료를 누른 직후 결과 화면에 닿기 전에** 앱이 죽은 경우는 적지 않는다.
- **디자인 · 구현**: 전에는 이 기기에 종료 의사가 남아 있어도 `/running` 이 「종료 처리 중인 러닝이에요」
  안내만 띄우고 결과 화면으로 넘기지 않았다. 이제 `TrackerGate` 가 판정을 시작할 때 **이 기기에 현재
  generation 의 종료 의사가 있으면 결과 화면으로 보낸다.** 「여기서 종료」뿐 아니라 **종료 슬라이드를 민
  writer 기기에도 똑같이 적용된다.**
  - generation 이 다르면 보내지 않는다 — 종료를 누른 뒤 다른 기기가 인수했다면 그 의사는 서버가 받아 줄 수
    없는 값이라, 결과 화면에서 재시도만 반복하게 된다. 그때는 read-only 로 보이고 다시 고른다.
- **고쳐야 할 곳**: `docs/05-policy.md` P14 의 결과 열과 `docs/07-screens.md:55` 에 「종료를 누른 뒤 결과 화면에
  닿기 전에 앱이 닫혔다면, 다시 열 때 결과 화면에서 종료 처리를 이어간다」를 덧붙인다.
